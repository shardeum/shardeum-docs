As a validator node runner, you typically use your node’s web UI dashboard to unstake tokens. The dashboard provides all essential information, including whether your node is currently active or in standby, and if your stake is locked - plus how long the lock remains. This stake lock is a critical security feature of the network, introducing a cooldown period between staking, unstaking, or switching node states. During this period, staking/unstaking are temporarily disabled to maintain network integrity.

For developers managing nodes programmatically-whether to stake across multiple nodes or to build a node hosting service - you can retrieve the same status information via the node’s APIs. This makes it possible to automate monitoring and unstaking processes without manual intervention.

In this guide, we will understand what is important in building such services:

## Understanding the Current Stake Status

The `shardeum-validator` image includes a CLI tool called `operator-cli` that simplifies querying a node’s status. Use the command `operator-cli status` to get a detailed overview.

add-image

This command returns an overview including the important state field, which can be one of: `Active`, `Stopped`, `Initializing`, `Standby`. A full list of node states is available in the [Node States documentation](https://docs.shardeum.org/docs/node/run/validator/node-states).

## When can you Unstake?

You can only unstake when your node is in the Stopped state.

- If your node is Active, stopping it will cause a penalty: you will lose all rewards earned during this session, and must wait hours or even days (depending on network conditions) before you can unstake. **Never try to unstake while active**.
- If your node is in Standby, it is safe to stop it using `operator-cli stop`. Then monitor the status every 5 seconds until it changes to Stopped. Once the node is Stopped, run `operator-cli unstake` to safely unstake your tokens.

## Unstaking without Node availability

If your node is offline (e.g. server failure, Docker container removed), you can still unstake by using the nominatorAddress (your wallet address) and nomineeAddress (node’s network identity). These addresses can be obtained from the output of `operator-cli status` while the node was running.

Using these, you can query the `/canUnstake` API endpoint on any active node in the network. The URL to query would be:

```bash
$NODE_IP:$NODE_PORT/canUnstake/<nomineeAddress>/<nominatorAddress>
```

If the stake is still locked due to the cooldown period, the API will return a response indicating the reason and the remaining time before unstaking is allowed. For example:

```bash
"stakeUnlocked": {
    "reason": "Stake lock period active from last staking/unstaking action.",
    "remainingTime": 424991,
    "unlocked": false
}
```

If the stake is unlocked, the response will confirm that unstaking can proceed.

```bash
"stakeUnlocked": {
    "reason": "",
    "remainingTime": 0,
    "unlocked": true
}
```

To find an active node to query, you can get the list of active nodes from the network’s archivers using the below URL:

```bash
http://35.238.248.68:4000/full-nodelist?activeOnly=true
```

This returns a list of active nodes, each with an id matching the nomineeAddress needed for the API call. Using this list, you can programmatically select any active node to check your staking status and unstake accordingly.
