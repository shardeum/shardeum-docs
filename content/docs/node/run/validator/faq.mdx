### Why am I seeing "Same destination load limit" when transferring funds?
This error occurs when you try to send multiple transactions to the same destination wallet address in quick succession. Shardeum enforces a rate limit that allows only one pending transaction per destination address at a time to prevent network congestion or abuse. To resolve this, make sure your transactions to the same wallet are sent sequentially—wait for the first transaction to be confirmed before initiating the next one.

### If I run 100+ Shardeum validator containers on a single host, do I need to open 200+ ports?
Yes, each validator container requires two unique ports: one for internal P2P communication (SHMINT) and one for external P2P communication (SHMEXT). So, for 100 validators, you would need 200 distinct ports open on the host. These ports must be open to the internet for the nodes to function properly.

### Can I choose any ports for SHMINT and SHMEXT? Do the container ports and host ports need to match when running multiple validators on the same host?
Yes, you can map any ports you like for SHMINT and SHMEXT as long as the following conditions are met:

- The SHMINT (internal P2P port) and SHMEXT (external P2P port) inside the container must be correctly set to the desired port numbers.
- The mapped ports must be accessible from the internet (not blocked by firewalls).
- **Important:** The container ports and the corresponding host ports must match. This is necessary because the validator advertises its IP and port combination to the network using the SHMINT and SHMEXT values. If the ports differ, other nodes won’t be able to connect, as the advertised ports won’t match the real accessible ports.

Note: The DASHPORT is optional and only used for accessing the validator’s dashboard UI. It’s not required for validator operation.

### How does the Shardeum network know how to reach each validator?
 When a validator starts, it uses built-in IPs for the monitor, archiver, and RPC servers to bootstrap itself into the network. It contacts the archiver node to fetch the latest network topology. The validator determines its own public IP and reads the SHMINT (internal P2P port) and SHMEXT (external P2P port) environment variables to know which ports to advertise. It then reports its public IP:PORT combination to the network, allowing other nodes to connect to it.

### How can I test if my validator ports are properly exposed to the internet?
You can run a curl command from a different server (not the validator host) to check if the ports are publicly reachable. For example:

```bash
curl http://<your-public-ip>:<SHMINT>/nodeinfo
````
