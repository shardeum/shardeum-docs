For true decentralization and censorship resistance, it's crucial to minimize reliance on cloud providers. Self-hosting your Shardeum validator on personal hardware offers several advantages:

1. Enhanced network security and resilience
2. Reduced risk of centralized points of failure
3. Greater control over your node's operation and data

Shardeum nodes are versatile and can run on various personal hardware platforms:

- Desktop computers
- Laptops
- Dedicated servers

While it's possible to run a validator on your everyday computer, it is generally recommended to use a dedicated machine for optimal performance and security. This approach ensures your validator operates consistently without interfering with your daily computing tasks.

By choosing to self-host, you're not just running a validator – you're actively contributing to the robustness and decentralization of the Shardeum network.


## Benefits of operating a Shardeum validator

- Earn SHM for securing the network.
- Contribute to the security, scalability and decentralization of Shardeum.


## Minimum Hardware Requirements

- 250 GB SSD storage
- Quad core CPU less than 10 years old if self hosting
- Dual core CPU works if hosted with newer Xeons / EPYC
- 16 GB of ram,  4+ GB of virtual memory recommended
- Hosting: 8 GB RAM + 8 GB Virtual Memory

### Using Docker

If you prefer to set up the validator directly using Docker, follow these steps:

```shell
docker pull ghcr.io/shardeum/shardeum-validator
docker run \
    --name shardeum-validator \
    -p 8080:8080 \
    -p 9001:9001 \
    -p 10001:10001 \
    -v $(pwd)/shardeum:/home/node/config \
    --restart=always \
    --detach \
    ghcr.io/shardeum/shardeum-validator:latest
docker exec -it shardeum-validator operator-cli gui set password "YOUR_NEW_PASSWORD"
```

<Callout title="" type="info">
Replace YOUR_NEW_PASSWORD with a secure password of your choice.
</Callout>

This will start the validator with the default ports, 8080 for the dashboard GUI, and `9001` and `10001` for the validator P2P ports. To change the default ports the validator uses, set the following environment variables. In this example:

- The dashboard GUI port is set to 10080.
- The validator P2P ports are set to 11001 (internal) and 12002 (external).

```shell
docker run \
    --name validator-dashboard \
    -p 10080:10080 \
    -p 11001:11001 \
    -p 12002:12002 \
    -e SHMINT=11001 \
    -e SHMEXT=12002 \
    -e DASHPORT=10080 \
    -v $(pwd)/shardeum:/home/node/config \
    --restart=always \
    --detach \
    ghcr.io/shardeum/shardeum-validator
```

To change the password for the dashboard GUI, run the `set-password.sh` script located in the `~/shardeum` directory:

```shell
cd ~/shardeum
./set-password.sh
```

<Callout title="" type="info">

Stake the specified minimum amount to start earning rewards.(For testnet, its 10 SHM)

<Callout title="" type="info">
If your node status is on Standby and you have 10 SHM or more staked, your validator node is setup correctly.

</Callout>

<Callout title="" type="info">

</Callout>

### How to Unstake a Node Previously Staked on Another Node

When you stake SHM tokens on a Shardeum validator node, those tokens are locked for a period of time (stake lock). During this period, you cannot immediately unstake and move your tokens to another node. This mechanism helps maintain network stability.

#### Prerequisites

- Access to the wallet that was used for staking
- Web3 wallet (like MetaMask) with your account connected
- Your stake lock period must have expired if you want to unstake normally

#### Unstaking Using the GUI

##### Check Your Stake Status

1. Login to your Shardeum validator dashboard
2. Connect the same wallet that was used for staking on the previous node
3. If your wallet has an active stake on another node, the GUI will inform you that you need to remove the stake from the previous node before staking on a new one

##### Wait for Stake Lock Expiration

1. The unstake button will be disabled until your stake lock period has expired
2. Once the lock period is over, the unstake button will become active

##### Unstaking Process

1. Click the "Remove Stake" button on the dashboard
2. Confirm the transaction in your Web3 wallet
3. Wait for the transaction to be confirmed on the network
4. Your SHM tokens will be returned to your wallet

#### Unstaking Using the CLI

You can also unstake using the command line interface:

1. Navigate to your validator directory
2. Use the following command:

```bash
operator-cli unstake
```

3. If your stake is locked, you'll see a message indicating the remaining time:

```bash
Unstaking not allowed yet: Stake is locked. Please wait X minutes Y seconds before trying again.
```

#### Common Issues

1. **Cannot Unstake**: If the unstake button is disabled or you receive an error, your stake is likely still locked. Wait for the lock period to expire.

2. **Node Recently Stopped**: If your node was stopped recently, you may need to wait at least 15 minutes before being able to unstake.

- Stop your validator before updating (you don't need to unstake though)
- In your terminal, first exit from the container using

<Tabs items={["Shell"]}>
```ts tab="Shell"
exit
cd ..
```
</Tabs>



- Run the following curl script

<Tabs items={["Shell"]}>
```ts tab="Shell"
curl -O https://raw.githubusercontent.com/shardeum/shardeum-validator/refs/heads/dev/install.sh && chmod +x install.sh && ./install.sh
```
</Tabs>


You might manually have to start the GUI afterwards. To do that, first get into the shell with:

<Tabs items={["Shell"]}>
```ts tab="Shell"
cd shardeum
./shell.sh
```
</Tabs>

Then start the GUI with:

<Tabs items={["Shell"]}>
```ts tab="Shell"
operator-cli gui start
```
</Tabs>


- Check your current version from either CLI or GUI and make sure it is the latest version.
