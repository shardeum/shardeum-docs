A validator node participates in block production and consensus on the Shardeum testnet. It is used to test validator operations, node performance, and network behavior in a live environment.

Validator requirements and staking behavior on testnet may differ from mainnet.

<Callout type="warn">
Testnet configurations, chain IDs, staking requirements, and token availability may change. Always refer to the latest repository or official announcements.
</Callout>

---

## 1. System Requirements

- Operating System: Ubuntu 22.04 LTS  
- CPU: 4 cores (8 threads recommended)  
- RAM: 16GB  
- Storage: 1TB NVMe SSD  
- Network: 100 Mbps dedicated  
- Dependencies: git, jq, curl, make, build-essential, pkg-config  
- Go: Version 1.25+  

### Install dependencies:

```bash
sudo apt update
sudo apt install git jq curl make build-essential pkg-config -y
```

### Install Go:

```bash
curl -LO https://go.dev/dl/go1.25.0.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.25.0.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
source ~/.bashrc
go version
```

## 2. Install Shardeum Node Binary

Clone the Shardeum EVM repository:

```bash
cd "$HOME"
git clone https://github.com/shardeum/shardeum-evm.git
cd shardeum-evm
```

Fetch the latest release tags and check out the currently supported testnet release:

```bash
git fetch --tags
git tag --list

TESTNET_RELEASE="REPLACE_WITH_SUPPORTED_TESTNET_TAG"
git checkout "$TESTNET_RELEASE"
```

Replace `REPLACE_WITH_SUPPORTED_TESTNET_TAG` with the release tag supported by the currently running Shardeum testnet. Ensure the selected release includes the correct testnet genesis file and network configuration before building.

Build and install the binary (may take several minutes):

```bash
make install
```

Add the Go bin directory to PATH:

```bash
echo 'export PATH=$PATH:$HOME/go/bin' >> ~/.bashrc
source ~/.bashrc
```

Verify the installation:

```bash
shardeumd version
command -v shardeumd
```

## 3. Set Environment Variables

```bash
export SHARDEUM_CONFIG_DIR="$PWD/config"
export SHARDEUM_NETWORK=testnet
export SHARDEUM_CHAIN_ID=shardeum-testnet
```

## 4. Initialize the Node

<Callout type="warn"> 
Ensure your validator keys and mnemonic are stored securely. Loss of your mnemonic may prevent recovery of the validator account. **Also:** Initialize only a new node directory. Do not rerun initialization with `--overwrite` on an existing validator without first securing its configuration, consensus keys, and signing state.
</Callout>

```bash
NODE_ID="node0"
MONIKER="shardeum-testnet-validator"

shardeumd init "$MONIKER" \
  --chain-id shardeum-testnet \
  --home $HOME/.testnet/$NODE_ID \
  --overwrite
```

## 5. Copy Genesis File

Copy the testnet genesis file from the repository:

```bash
cp config/environments/testnet-genesis.json \
  "$HOME/.testnet/$NODE_ID/config/genesis.json"
```

Verify that the genesis file matches the expected chain ID:

```bash
jq -e '.chain_id == "shardeum-testnet"' \
  "$HOME/.testnet/$NODE_ID/config/genesis.json"
```

The command should return `true`. If verification fails, confirm that you are using the correct testnet genesis file before proceeding.

## 6. Start and Sync the Node

```bash
shardeumd start \
  --home $HOME/.testnet/$NODE_ID \
  --chain-id shardeum-testnet \
  --p2p.seeds "c15cdf69a0332a29a12b448ecf310b39d1d7659d@34.57.163.115:27656,1d6f78c5a0d3302b3b3ee963a9414b4909a5032f@34.170.136.184:27656,2773057c346152646bb71639dcc88828d1bbd1cf@34.63.57.148:27656" \
  --p2p.laddr tcp://0.0.0.0:27656 \
  --rpc.laddr tcp://127.0.0.1:26657 \
  > $HOME/.testnet/$NODE_ID/node.log &
```

**Monitor node logs:**

```bash
tail -f $HOME/.testnet/$NODE_ID/node.log
```

Verify sync status:

```bash
shardeumd status --home $HOME/.testnet/$NODE_ID | jq '.SyncInfo'
```

**Note**: Initial sync may take time depending on hardware and network conditions.

## 7. Create the Validator Key

<Callout type="warn">
Ensure the node is connected to peers and wait until it is fully synced before proceeding.
</Callout>

```bash
shardeumd keys add validator-key \
  --home $HOME/.testnet/$NODE_ID
```

Or recover:

```bash
shardeumd keys add validator-key --recover \
  --home $HOME/.testnet/$NODE_ID
```

Retrieve your validator address:

```bash
shardeumd keys show validator-key -a \
  --home $HOME/.testnet/$NODE_ID
```

<Callout type="warn"> 
Store your mnemonic phrase securely. It is required for recovery. Also, the operator may be prompted for a keyring passphrase.
</Callout>

## 8. Fund Your Validator (Testnet)

<Callout type="info"> 
Your validator account needs testnet SHM to stake and pay transaction fees. Use official testnet faucets or community distribution channels to obtain testnet SHM.
</Callout>

Verify balance:

```bash
VALIDATOR_ADDRESS=$(shardeumd keys show validator-key -a \
  --home $HOME/.testnet/$NODE_ID)

shardeumd query bank balances "$VALIDATOR_ADDRESS" \
  --home $HOME/.testnet/$NODE_ID
```

## 9. Create Your Validator and Stake Testnet SHM

Get consensus key:

```bash
shardeumd comet show-validator --home $HOME/.testnet/$NODE_ID
```

The command returns a JSON object containing the validator's consensus public key. Copy the value of its `key` field into the corresponding field in `validator.json`. Keep the `@type` field unchanged.

Create the validator configuration file:

```bash
nano validator.json
```

Paste the following JSON template, replace the placeholder values, and save the file before creating the validator.

<Callout type="info">
Adjust the stake amount based on current testnet requirements and your available testnet SHM balance.
</Callout>

```json
{
  "pubkey": {
    "@type": "/cosmos.crypto.ed25519.PubKey",
    "key": "<your consensus key>"
  },
  "amount": "1000000000000000000ashm",
  "moniker": "<your validator name>",
  "commission-rate": "0.10",
  "commission-max-rate": "0.20",
  "commission-max-change-rate": "0.01",
  "min-self-delegation": "1"
}
```

Create validator:

```bash
shardeumd tx staking create-validator validator.json \
  --from=validator-key \
  --chain-id shardeum-testnet \
  --home $HOME/.testnet/$NODE_ID \
  --gas="auto" \
  --gas-adjustment="1.5"
```

> **Transaction fees:** The command uses automatic gas estimation. If the transaction is rejected due to insufficient fees, specify `--gas-prices` using a value accepted by the current testnet. Ensure your account holds enough testnet SHM to cover both staking and transaction fees.

## 10. Verify Validator Status

```bash
VALIDATOR_OPERATOR_ADDRESS=$(shardeumd keys show validator-key \
  --bech val \
  -a \
  --home $HOME/.testnet/$NODE_ID)

shardeumd query staking validator "$VALIDATOR_OPERATOR_ADDRESS" \
  --home $HOME/.testnet/$NODE_ID
```

Look for:
- Status: `BOND_STATUS_BONDED`
- Voting power: greater than `0`
- Jailed: `false`

Note: A successfully registered validator may not immediately be bonded. `BOND_STATUS_BONDED` and positive voting power indicate active validator-set participation, whereas an unbonded validator may be waiting to enter the active set.

## 11. Optional: Run as a systemd Service

**Check the installed Shardeum binary path:**

```bash
command -v shardeumd
```

**Create the service file:**

```bash
sudo nano /etc/systemd/system/shardeumd-testnet.service
```

Example content:

> **Example configuration:** The service below assumes that Shardeum was installed under `/root` and initialized using `NODE_ID="node0"`. Adjust the system user, binary path, configuration directory, and node-home path to match your installation. For production validators, a dedicated non-root user is recommended.

```ini
[Unit]
Description=Shardeum Testnet Validator
Wants=network-online.target
After=network-online.target

[Service]
User=root
Environment="SHARDEUM_NETWORK=testnet"
Environment="SHARDEUM_CHAIN_ID=shardeum-testnet"
Environment="SHARDEUM_CONFIG_DIR=/root/shardeum-evm/config"
ExecStart=<shardeumd-binary-path> start \
  --home /root/.testnet/node0 \
  --chain-id shardeum-testnet \
  --p2p.seeds "c15cdf69a0332a29a12b448ecf310b39d1d7659d@34.57.163.115:27656,1d6f78c5a0d3302b3b3ee963a9414b4909a5032f@34.170.136.184:27656,2773057c346152646bb71639dcc88828d1bbd1cf@34.63.57.148:27656" \
  --p2p.laddr tcp://0.0.0.0:27656 \
  --rpc.laddr tcp://127.0.0.1:26657
Restart=on-failure
RestartSec=3
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

Replace `<shardeumd-binary-path>` with the absolute path returned by `command -v shardeumd`. If you selected a different node ID, update the `--home` path accordingly.

If the validator is already running from the manual startup command above, stop that process before starting the systemd service.

**Reload systemd, then enable and start the service:**

```bash
sudo systemctl daemon-reload
sudo systemctl enable shardeumd-testnet
sudo systemctl start shardeumd-testnet
sudo systemctl status shardeumd-testnet
```

Check the service logs and confirm that the node's block height continues advancing:

```bash
sudo journalctl -u shardeumd-testnet -n 50 --no-pager

curl -s http://127.0.0.1:26657/status \
  | jq -r '.result.sync_info.latest_block_height'
```

Run the block-height command again after a short interval to verify progress.

## 12. Important Notes

- Testnet Chain ID: `shardeum-testnet`
- EVM Chain ID: `8119`
- Network: Shardeum EVM Testnet (subject to resets)
- Testnet SHM has no real-world monetary value.
- Testnet configuration and validator state may be reset or changed between testnet phases.
- Staking, slashing, validator-set parameters, and other network settings may differ from mainnet.

## Validator Setup Complete

Your Shardeum testnet validator is now configured and participating in the network when bonded.

You can use the testnet validator environment for:

- Validator operations and testing
- Upgrade and maintenance testing
- Performance monitoring
- Network participation experiments
