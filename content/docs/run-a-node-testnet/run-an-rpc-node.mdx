An RPC node provides JSON-RPC and WebSocket endpoints for developers, dApps, indexers, infrastructure providers, and testing or integration environments. RPC nodes verify chain data but do not participate in consensus or require staking.

<Callout type="warn">
Do not expose the node's CometBFT RPC endpoint publicly. Only expose application RPC endpoints that are required for your deployment, and protect them with appropriate access controls and rate limiting.
</Callout>

## 1. System Requirements

Recommended:

- OS: Ubuntu 22.04 LTS
- CPU: 4 cores
- RAM: 8–16 GB
- Storage: 500 GB+ NVMe SSD
- Network: High-bandwidth connection
- Dependencies: git, jq, curl, make, build-essential, pkg-config
- Go: v1.25+

### Install dependencies:

```bash
sudo apt update
sudo apt install git jq curl make build-essential pkg-config -y
```

### Install Go

```bash
curl -LO https://go.dev/dl/go1.25.0.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.25.0.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
source ~/.bashrc
go version
```

## 2. Install Shardeum Node Binary

Clone the Shardeum EVM repository:

```bash
git clone https://github.com/shardeum/shardeum-evm.git
cd shardeum-evm
```

Fetch the latest release tags and check out the currently supported testnet release:

```bash
git fetch --tags
git tag --list

TESTNET_RELEASE="REPLACE_WITH_SUPPORTED_TESTNET_TAG"
git checkout "$TESTNET_RELEASE"
```

Replace `REPLACE_WITH_SUPPORTED_TESTNET_TAG` with the release tag supported by the currently running Shardeum testnet. Ensure the selected release includes the correct testnet genesis file and network configuration before building the binary.

Build and install the binary (may take several minutes):

```bash
make install
```

Add the Go bin directory to PATH:

```bash
echo 'export PATH=$PATH:$HOME/go/bin' >> ~/.bashrc
source ~/.bashrc
```

Verify the installation:

```bash
shardeumd version
command -v shardeumd
```

## 3. Environment Variables

```bash
export SHARDEUM_CONFIG_DIR="$PWD/config"
export SHARDEUM_NETWORK=testnet
```

## 4. Initialize the Node

```bash
NODE_ID="rpcnode"
MONIKER="shardeum-testnet-rpc"

shardeumd init "$MONIKER" \
  --chain-id shardeum-testnet \
  --home $HOME/.testnet/$NODE_ID \
  --overwrite
```

## 5. Copy Genesis File

```bash
cp config/environments/testnet-genesis.json \
  "$HOME/.testnet/$NODE_ID/config/genesis.json"

jq -e '.chain_id == "shardeum-testnet"' \
  "$HOME/.testnet/$NODE_ID/config/genesis.json"
```

The expected chain ID is:

```text
shardeum-testnet
```

## 6. Configure Pruning

For a typical RPC node, custom pruning helps manage storage while retaining recent state.

Edit:

`$HOME/.testnet/$NODE_ID/config/app.toml`

Set:

```toml
pruning = "custom"
pruning-keep-recent = "10000"
pruning-interval = "50"
```

If you require complete historical state, run an Archive Node instead using:

```toml
pruning = "nothing"
```

## 7. Enable JSON-RPC

Edit:

`$HOME/.testnet/$NODE_ID/config/app.toml`

Under the existing `[json-rpc]` section, set:

```toml
enable = true
address = "127.0.0.1:8545"
ws-address = "127.0.0.1:8546"
```

## 8. Start and Sync the Node

Start:

```bash
shardeumd start \
  --home $HOME/.testnet/$NODE_ID \
  --chain-id shardeum-testnet \
  --p2p.seeds "c15cdf69a0332a29a12b448ecf310b39d1d7659d@34.57.163.115:27656,1d6f78c5a0d3302b3b3ee963a9414b4909a5032f@34.170.136.184:27656,2773057c346152646bb71639dcc88828d1bbd1cf@34.63.57.148:27656" \
  --p2p.laddr tcp://0.0.0.0:27656 \
  --rpc.laddr tcp://127.0.0.1:26657 \
  > $HOME/.testnet/$NODE_ID/node.log &
```

Verify sync status:

```bash
shardeumd status --home $HOME/.testnet/$NODE_ID | jq '.SyncInfo'
```

Or tail the log:

```bash
tail -f $HOME/.testnet/$NODE_ID/node.log
```

Wait until fully synced.

## 9. Optional: Enable gRPC and REST Endpoints

Edit:

`$HOME/.testnet/$NODE_ID/config/app.toml`

Under the existing `[grpc]` section, set:

```toml
enable = true
address = "127.0.0.1:9090"
```

Under the existing `[api]` section, set:

```toml
enable = true
address = "tcp://127.0.0.1:1317"
```

Enable these only if required by your infrastructure or testing flow.

Restart the node after making changes.

If using systemd:

```bash
sudo systemctl restart shardeumd-rpc-testnet
```

## 10. Firewall Configuration

Before enabling UFW, allow SSH access so you do not lock yourself out:

```bash
sudo ufw allow OpenSSH
```

Allow P2P traffic:

```bash
sudo ufw allow 27656/tcp
```

The JSON-RPC, WebSocket, gRPC, and REST endpoints are configured to listen on localhost, so their backend ports do not need to be opened publicly.

For externally accessible RPC services, use a secure reverse proxy with HTTPS/WSS, rate limiting, and appropriate access controls. Allow the proxy's public HTTPS port (typically `443/tcp`) while keeping the backend ports restricted.

If direct external access is specifically required, configure the appropriate listening addresses and limit firewall access to trusted IP addresses or networks.

If the HTTPS reverse proxy runs on this server, allow HTTPS traffic before enabling UFW:

```bash
sudo ufw allow 443/tcp
```

Skip this rule if HTTPS is terminated elsewhere and this server does not need to accept public HTTPS connections.

Then enable and check the firewall:

```bash
sudo ufw enable
sudo ufw status
```

<Callout type="error"> 
Do not expose port `26657` (CometBFT RPC) publicly. Restrict sensitive endpoints to localhost or trusted systems, and protect public RPC endpoints with suitable rate limiting and reverse-proxy controls.
</Callout>

## 11. systemd Service (Recommended)

**Check the installed Shardeum binary path:**

```bash
command -v shardeumd
```

Create the service file:

```bash
sudo nano /etc/systemd/system/shardeumd-rpc-testnet.service
```

Example content:

> The example below assumes the node was installed and initialized as the `root` user. If you used another system user, replace `User=root` and `/root/.testnet/rpcnode` with the corresponding user and node-home path.

```ini
[Unit]
Description=Shardeum Testnet RPC Node
Wants=network-online.target
After=network-online.target

[Service]
User=root
Environment="SHARDEUM_NETWORK=testnet"
Environment="SHARDEUM_CHAIN_ID=shardeum-testnet"
Environment="SHARDEUM_CONFIG_DIR=/root/shardeum-evm/config"
ExecStart=<shardeumd-binary-path> start \
  --home /root/.testnet/rpcnode \
  --chain-id shardeum-testnet \
  --p2p.seeds "c15cdf69a0332a29a12b448ecf310b39d1d7659d@34.57.163.115:27656,1d6f78c5a0d3302b3b3ee963a9414b4909a5032f@34.170.136.184:27656,2773057c346152646bb71639dcc88828d1bbd1cf@34.63.57.148:27656" \
  --p2p.laddr tcp://0.0.0.0:27656 \
  --rpc.laddr tcp://127.0.0.1:26657
Restart=on-failure
RestartSec=3
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

Replace `<shardeumd-binary-path>` with the path returned by `command -v shardeumd`.

If the node is already running from the manual startup command, stop that process before starting the systemd service.

Reload systemd, then enable and start the service:

```bash
sudo systemctl daemon-reload
sudo systemctl enable shardeumd-rpc-testnet
sudo systemctl start shardeumd-rpc-testnet
sudo systemctl status shardeumd-rpc-testnet
```

Confirm that the service is running and that the node's block height continues advancing:

```bash
curl -s http://127.0.0.1:26657/status \
  | jq -r '.result.sync_info.latest_block_height'
```

Run the command again after a short interval to verify progress.

## 12. Scaling RPC Nodes (Optional)

For higher traffic or team-based testing:

- Use load balancers such as Nginx, HAProxy, or AWS ELB
- Run multiple RPC nodes behind a reverse proxy
- Rate-limit requests to avoid overload
- Separate public RPC from internal infrastructure RPC
- Run dedicated indexing services in parallel where required



```bash
journalctl -u shardeumd-rpc-testnet -f
```

### Query JSON-RPC:

```bash
curl -s http://localhost:8545 \
  -X POST \
  -H "Content-Type: application/json" \
  --data '{"jsonrpc":"2.0","method":"eth_chainId","params":[],"id":1}'
```

## 14. Troubleshooting

### RPC endpoint not responding

- Confirm JSON-RPC is enabled in `app.toml`
- Confirm IP binding is correct
- Check firewall rules
- Check that the node is fully synced

### High latency

- Check CPU, memory, disk I/O, and network utilization
- Review RPC request volume and rate limits
- Confirm that the node remains fully synced
- Add additional RPC nodes behind a proxy if required

### Node stuck catching up

- Check peers
- Restart node
- Verify time sync (NTP)
- Confirm you are using the correct testnet chain ID and genesis file

## 15. Important Notes

- Testnet Chain ID: `shardeum-testnet`
- EVM Chain ID: `8119`
- Network: Shardeum EVM Testnet (subject to change)
- Genesis File: Use the testnet genesis file included with the supported release.
- Archive Mode: Use `pruning = "nothing"` only when complete historical state is required.
- Testnet configuration may change between testnet phases.
