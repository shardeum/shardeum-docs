# Architecture Overview

Shardeum is an EVM-compatible Layer 1 blockchain built on the Cosmos SDK, designed to bring India - and the world - onchain with low fees, fast finality, and high scalability.

## Core Technology Stack

Shardeum's architecture is built on three foundational technologies:

### 1. Cosmos SDK

Shardeum leverages the **Cosmos SDK**, the leading development framework for building interoperable sovereign blockchains. The Cosmos SDK provides:

- **Modular architecture** that allows new features to be added without disrupting the network
- **Battle-tested consensus** with proven security and stability
- **IBC compatibility** enabling future cross-chain communication
- **Flexible governance** mechanisms for protocol upgrades

### 2. EVM Compatibility Layer

Shardeum implements **full EVM (Ethereum Virtual Machine) compatibility**, enabling seamless deployment of Ethereum dApps and smart contracts:

- **Solidity & Vyper support** - Deploy existing Ethereum smart contracts without modification
- **Ethereum tooling** - Compatible with MetaMask, Hardhat, Foundry, Remix, and other Ethereum tools
- **Web3 API** - Standard JSON-RPC endpoints for seamless integration
- **Leading dApps** - Run Uniswap, Aave, and other major Ethereum protocols natively

The EVM layer is implemented through a custom integration that bridges Ethereum execution with Cosmos SDK state management, providing developers with the familiarity of Ethereum while benefiting from Cosmos infrastructure.

### 3. Consensus Mechanism

Shardeum uses **Proof-of-Stake (PoS) consensus** with:

- **Fast finality** - Transaction confirmation in seconds
- **Delegated staking** - Token holders can delegate SHM to validators
- **Validator network** - Decentralized set of validators securing the network
- **Slashing protection** - Economic security through stake-based penalties

## Network Architecture

### Chain Specifications

- **Chain ID (Cosmos):** `shardeum_8118-1`
- **Chain ID (EVM):** `8118` (hex: `0x1fb6`)
- **Native Token:** SHM
- **Block Time:** ~2-3 seconds
- **Consensus:** Tendermint BFT

### Key Components

**1. Application Layer (EVM)**
- Smart contract execution environment
- State management for accounts and contracts
- Transaction processing and validation
- Gas metering and fee collection

**2. Consensus Layer (Tendermint)**
- Block proposal and validation
- Byzantine Fault Tolerant consensus
- Network synchronization
- Fork resolution

**3. State Management**
- Account state (balances, nonces)
- Contract storage
- Validator set tracking
- Staking and delegation records

## Network Participants

### Validators

Validators are responsible for:
- Proposing and validating blocks
- Maintaining network consensus
- Processing transactions
- Securing the network through staked SHM

**Minimum stake:** 1 SHM
**Unbonding period:** 21 days

### Delegators

Token holders can participate in network security by:
- Delegating SHM to validators
- Earning staking rewards
- Participating in governance (future)

### Full Nodes

Full nodes support the network by:
- Maintaining complete blockchain history
- Serving RPC requests for dApps
- Relaying transactions
- Providing data to light clients

## Developer Integration

### Smart Contract Development

Developers can deploy smart contracts using:

```solidity
// Standard Solidity contracts work without modification
pragma solidity ^0.8.0;

contract Example {
    function hello() public pure returns (string memory) {
        return "Hello Shardeum";
    }
}
```

### Network Connection

Connect to Shardeum using standard Ethereum tools:

**RPC Endpoint:** `https://api.shardeum.org`
**Chain ID:** `8118`
**Block Explorer:** `https://explorer.shardeum.org`

### Transaction Processing

1. User submits transaction via Web3 wallet or dApp
2. Transaction is broadcast to validator nodes
3. Validators include transaction in proposed block
4. Consensus is reached on block validity
5. Block is committed and transaction is finalized
6. State is updated and receipt is generated

## Key Features

### 1. EVM Compatibility

- **Seamless migration** from Ethereum and other EVM chains
- **No code changes** required for existing smart contracts
- **Familiar tooling** for developers (Hardhat, Truffle, Foundry)
- **Standard interfaces** (ERC-20, ERC-721, ERC-1155)

### 2. Low Transaction Fees

- **Predictable costs** through efficient consensus
- **SHM-denominated gas** with stable pricing
- **Optimized execution** reducing computational overhead

### 3. Fast Finality

- **Instant confirmation** for better user experience
- **No reorganizations** after block finalization
- **Reliable state** for time-sensitive applications

### 4. High Throughput

- **Efficient block production** with ~2-3 second block times
- **High gas limit** supporting complex transactions
- **Optimized state management** for scalability

### 5. Modular Design

- **Upgradeable components** through governance
- **Plugin architecture** for new features
- **Flexible module system** inherited from Cosmos SDK

## Security Model

### Economic Security

- **Proof-of-Stake** with validator slashing for misbehavior
- **Stake-weighted voting** in consensus
- **Penalty mechanisms** for downtime and double-signing

### Technical Security

- **Audited codebase** built on proven Cosmos SDK foundation
- **EVM security** leveraging Ethereum's battle-tested execution layer
- **Byzantine Fault Tolerance** protecting against malicious validators

### Operational Security

- **Distributed validator set** preventing single points of failure
- **Monitoring and alerting** for validator operators
- **Regular security updates** and patches

- Low fees and fast finality

Advanced scaling features to support global adoption:
