# APIs and Interfaces

Shardeum provides multiple API layers to support different types of interactions with the network. As an EVM-compatible blockchain built on Cosmos SDK, developers can use familiar Ethereum APIs alongside Cosmos-native endpoints.

## API Architecture

Shardeum's API stack consists of three main layers:

1. **EVM JSON-RPC API** - Standard Ethereum-compatible interface
2. **Cosmos SDK API** - REST and gRPC endpoints for chain operations
3. **Explorer API** - Blockchain data indexing and querying

## 1. EVM JSON-RPC API

### Overview

The JSON-RPC API provides full Ethereum compatibility, allowing developers to interact with Shardeum using standard Web3 libraries like ethers.js, web3.js, and viem.

**Mainnet RPC Endpoint:**
```
https://api.shardeum.org
```

**Chain ID:** `8118` (hex: `0x1fb6`)

### Supported Methods

Shardeum supports all standard Ethereum JSON-RPC methods:

#### Account Methods

```javascript
// Get account balance
eth_getBalance

// Get transaction count (nonce)
eth_getTransactionCount

// Get code at address
eth_getCode
```

#### Block Methods

```javascript
// Get latest block number
eth_blockNumber

// Get block by number or hash
eth_getBlockByNumber
eth_getBlockByHash
```

#### Transaction Methods

```javascript
// Send raw transaction
eth_sendRawTransaction

// Get transaction by hash
eth_getTransactionByHash

// Get transaction receipt
eth_getTransactionReceipt

// Estimate gas
eth_estimateGas

// Get gas price
eth_gasPrice
```

#### Smart Contract Methods

```javascript
// Call contract (read-only)
eth_call

// Get logs/events
eth_getLogs

// Get storage at position
eth_getStorageAt
```

#### Network Methods

```javascript
// Get chain ID
eth_chainId

// Get network version
net_version

// Get peer count
net_peerCount
```

### Example: Connecting with ethers.js

```javascript
import { ethers } from 'ethers';

// Create provider
const provider = new ethers.JsonRpcProvider('https://api.shardeum.org');

// Get block number
const blockNumber = await provider.getBlockNumber();
console.log('Current block:', blockNumber);

// Get account balance
const balance = await provider.getBalance('0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb');
console.log('Balance:', ethers.formatEther(balance), 'SHM');

// Send transaction
const wallet = new ethers.Wallet(privateKey, provider);
const tx = await wallet.sendTransaction({
  to: '0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb',
  value: ethers.parseEther('1.0')
});
await tx.wait();
```

### Example: Deploying Contract

```javascript
// Deploy ERC-20 token
const Contract = await ethers.getContractFactory('MyToken', wallet);
const token = await Contract.deploy();
await token.waitForDeployment();

console.log('Token deployed to:', await token.getAddress());
```

### WebSocket Support

For real-time event subscriptions:

```javascript
const ws = new ethers.WebSocketProvider('wss://api.shardeum.org');

// Subscribe to new blocks
ws.on('block', (blockNumber) => {
  console.log('New block:', blockNumber);
});

// Subscribe to pending transactions
ws.on('pending', (txHash) => {
  console.log('Pending tx:', txHash);
});
```

## 2. Cosmos SDK APIs

### REST API (LCD)

The Cosmos SDK REST API (Light Client Daemon) provides access to chain state and Cosmos-specific operations.

**Mainnet LCD Endpoint:**
```
https://lcd.shardeum.org
```

#### Common Endpoints

**Bank Module (Token Transfers)**

```bash
# Get account balance
GET /cosmos/bank/v1beta1/balances/{address}

# Get total supply
GET /cosmos/bank/v1beta1/supply
```

**Staking Module (Validators & Delegation)**

```bash
# List validators
GET /cosmos/staking/v1beta1/validators

# Get validator details
GET /cosmos/staking/v1beta1/validators/{validatorAddr}

# Get delegations for address
GET /cosmos/staking/v1beta1/delegations/{delegatorAddr}

# Get validator delegations
GET /cosmos/staking/v1beta1/validators/{validatorAddr}/delegations
```

**Distribution Module (Rewards)**

```bash
# Get delegation rewards
GET /cosmos/distribution/v1beta1/delegators/{delegatorAddr}/rewards

# Get validator commission
GET /cosmos/distribution/v1beta1/validators/{validatorAddr}/commission
```

**Governance Module (Proposals)**

```bash
# List proposals
GET /cosmos/gov/v1beta1/proposals

# Get proposal details
GET /cosmos/gov/v1beta1/proposals/{proposalId}

# Get votes for proposal
GET /cosmos/gov/v1beta1/proposals/{proposalId}/votes
```

### gRPC API

For high-performance applications, use gRPC endpoints:

**Mainnet gRPC Endpoint:**
```
grpc.shardeum.org:9090
```

#### Example: Query with grpcurl

```bash
# List validators
grpcurl grpc.shardeum.org:9090 cosmos.staking.v1beta1.Query/Validators

# Get account balance
grpcurl -d '{"address": "shardeum1..."}' \
  grpc.shardeum.org:9090 \
  cosmos.bank.v1beta1.Query/AllBalances
```

#### Example: JavaScript gRPC Client

```javascript
import { StargateClient } from '@cosmjs/stargate';

const client = await StargateClient.connect('https://rpc.shardeum.org');

// Get account
const account = await client.getAccount('shardeum1...');
console.log(account);

// Get balance
const balance = await client.getAllBalances('shardeum1...');
console.log(balance);
```

## 3. Explorer API

The Shardeum Explorer provides REST endpoints for querying indexed blockchain data.

**Mainnet Explorer API:**
```
https://explorer.shardeum.org/api
```

### Endpoints

#### Blocks

```bash
# Get latest blocks
GET /api/blocks

# Get block by number
GET /api/block/{blockNumber}

# Get block transactions
GET /api/block/{blockNumber}/transactions
```

#### Transactions

```bash
# Get transaction by hash
GET /api/transaction/{txHash}

# Get transactions for address
GET /api/transactions?address={address}&page={page}

# Get transactions in cycle range
GET /api/transaction?startCycle={start}&endCycle={end}&address={address}
```

#### Accounts

```bash
# Get account information
GET /api/account/{address}

# Get account transactions
GET /api/account/{address}/transactions

# Get account token balances
GET /api/account/{address}/tokens
```

#### Contracts

```bash
# Get contract information
GET /api/contract/{address}

# Verify contract source code
POST /api/contract/verify
```

### Example: Fetch Transaction

```javascript
async function getTransaction(txHash) {
  const response = await fetch(
    `https://explorer.shardeum.org/api/transaction/${txHash}`
  );
  const data = await response.json();
  return data;
}

const tx = await getTransaction('0x123...');
console.log(tx);
```

### Example: Monitor Address Activity

```javascript
async function getAddressTransactions(address, page = 1) {
  const response = await fetch(
    `https://explorer.shardeum.org/api/transactions?address=${address}&page=${page}`
  );
  const data = await response.json();
  return data;
}

const txs = await getAddressTransactions('0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb');
console.log(txs);
```

## 4. Event Listening

### Using eth_getLogs (EVM Events)

Monitor smart contract events using standard Ethereum logs:

```javascript
// Listen for ERC-20 Transfer events
const filter = {
  address: '0x...', // Token contract address
  topics: [
    ethers.id('Transfer(address,address,uint256)') // Event signature
  ],
  fromBlock: 'latest'
};

const logs = await provider.getLogs(filter);
console.log('Transfer events:', logs);
```

### WebSocket Subscriptions

Real-time updates via WebSocket:

```javascript
const ws = new ethers.WebSocketProvider('wss://api.shardeum.org');

// Subscribe to new pending transactions
const filter = { address: contractAddress };
ws.on(filter, (log) => {
  console.log('New event:', log);
});
```

### Polling with Cycles

For applications needing historical event data, use the Explorer API with cycle-based queries:

```javascript
// Get current cycle (latest block / 10, rounded down)
const latestBlock = await provider.getBlockNumber();
const currentCycle = Math.floor(latestBlock / 10);

// Query transactions in cycle range
const url = `https://explorer.shardeum.org/api/transaction?startCycle=${currentCycle}&endCycle=${currentCycle}&address=${address}`;
const response = await fetch(url);
const transactions = await response.json();
```

## Rate Limits

Public RPC endpoints have the following rate limits:

- **Requests per second:** 10
- **Requests per minute:** 600
- **Concurrent connections:** 5

For higher limits, consider running your own [RPC node](/docs/run-a-node/run-an-rpc-node).

## Best Practices

### 1. Use Appropriate API Layer

- **EVM interactions** → Use JSON-RPC
- **Staking/delegation** → Use Cosmos LCD/gRPC
- **Historical queries** → Use Explorer API

### 2. Handle Errors Gracefully

```javascript
try {
  const balance = await provider.getBalance(address);
} catch (error) {
  if (error.code === 'TIMEOUT') {
    // Retry logic
  }
  console.error('Error fetching balance:', error);
}
```

### 3. Batch Requests

For multiple queries, use batch RPC calls:

```javascript
const batch = [
  { method: 'eth_getBalance', params: [address1, 'latest'] },
  { method: 'eth_getBalance', params: [address2, 'latest'] }
];

// Implementation depends on your RPC client
```

### 4. Cache Results

Cache frequently accessed data to reduce API calls:

```javascript
const cache = new Map();

async function getBlockWithCache(blockNumber) {
  if (cache.has(blockNumber)) {
    return cache.get(blockNumber);
  }

  const block = await provider.getBlock(blockNumber);
  cache.set(blockNumber, block);
  return block;
}
```
